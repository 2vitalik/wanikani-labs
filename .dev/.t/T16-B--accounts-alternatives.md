## 1. Ключ акаунта (`accounts._id` = `account` у history/events)

| варіант | + | − |
|---|---|---|
| a) **`main`/`light` лишити, нові = `wk_id[:8]`** (обрано) | нуль міграції; ключ детермінований з WK-ідентичності → re-add зшиває історію; короткий у логах | два стилі ключів у базі (косметика) |
| b) повний UUID WK для всіх (+ міграція старих) | однорідно, унікальність з коробки | переписати 218 704 `history` + events + assignments + sync_state; 36-символьні ключі в логах і `sync_state` |
| c) username WK як ключ | читабельно | username змінюється (`user_updated` це вже ловить) → ключ у історії застаріває, зміна = міграція |
| d) користувач сам вводить ключ (як ти назвав main/light) | звично тобі | зайвий крок для чужих; валідація/унікальність; `label` це покриває |

## 2. Токени в Mongo

| варіант | + | − |
|---|---|---|
| a) **Fernet + `WKLABS_SECRET_KEY` в env** (обрано) | дампи/бекапи не містять робочих токенів; ~20 рядків коду | ще один секрет; втрата ключа = усі перевводять токени (їх одиниці); restore на іншій машині потребує того ж ключа |
| b) відкритим текстом (Mongo з auth, localhost) | найпростіше | кожен `mongodump` (runbook §8, Dropbox, ноут) — копія токенів; для чужих людей неприйнятно |
| c) KMS / age / sops | «правильно» | інфраструктура заради двох десятків токенів |

Read-only токен WK дає читати прогрес, не змінювати — витік неприємний, не фатальний; але для публічного бота стандарт — шифрувати.

## 3. Модель доставки

| варіант | + | − |
|---|---|---|
| a) один чат на акаунт (`accounts.delivery = {chat_id, layout}`), топіки виводяться з layout | мінімум таблиць | `subjects`/`system` — не per-account; вимкнути лише milestones — нема куди; T07 §4 однаково веде до маршрутів → переробка |
| b) **`routes (account \| null, category) → (chat, thread)` + `chats`** (обрано) | пряме узагальнення `routing.py` + `tg_topics`; on/off на категорію; глобальні категорії природні; шар `settings` на маршруті — під T07 | дві нові колекції; Notifier групує за маршрутом, не за топіком |
| c) повні «підписки»: користувач × акаунт × категорія × чат × режим | максимум гнучкості | завелике для пілота; режими (session/daily) — крок 2, не зараз |

## 4. Доступ нових людей

| варіант | + | − |
|---|---|---|
| a) **approve адміном** (обрано; env `ACCESS_POLICY=approve`) | нуль випадкових людей на твоєму сервері; ~30 рядків; кнопки ✅/🚫 у `system` | треба тиснути кнопку (раз на людину) |
| b) invite-код | самообслуговування для друзів | генерація/зберігання/ліміти кодів — більше коду; коди витікають |
| c) open | нуль тертя | будь-хто додає токени → ресурси, підтримка; для публічного релізу — окреме рішення пізніше |
| d) closed (адмін додає id) | максимум контролю | людина не може навіть «постукати» |

Політика — env-перемикач (зміна = рестарт); UI-перемикач у `/admin` — коли знадобиться.

## 5. Стан діалогів (FSM)

| варіант | + | − |
|---|---|---|
| a) **`MemoryStorage`** (обрано) | нуль коду; діалоги — один крок (токен / назва) | рестарт посеред діалогу → «надішли /accounts ще раз» |
| b) свій Mongo-storage над pymongo async | переживає рестарт | ~60 рядків (aiogram-ів `MongoStorage` — на motor); для ревʼю через бота (T07 §5) стан батчу однаково буде у власних колекціях, не у FSM |

## 6. Purge даних акаунта

| варіант | + | − |
|---|---|---|
| a) **лише CLI `accounts purge --yes`, лише для `removed`** (обрано) | випадково знищити `history` `main` з телефона неможливо | «видалити мої дані» від чужої людини — через адміна (до публічного релізу — норм) |
| b) кнопка в боті з confirm (ввести назву) | самообслуговування | ризик для твоїх акаунтів; confirm-и люди проклікують |
| c) кнопка лише для не-адмінських акаунтів | компроміс | дві логіки; відкласти до публічного релізу |

## 7. Bootstrap із env

| варіант | + | − |
|---|---|---|
| a) **авто на старті, ідемпотентно, Mongo — істина** (обрано) | vv3 і локальна база переходять без рук; env далі не перебиває | «магія» на старті (один рядок у лог знімає) |
| b) лише `wklabs accounts import-env` руками | явно | ще один крок runbook на кожній базі |
| c) env — істина для «своїх», Mongo — для чужих | нічого не імпортувати | два шляхи в коді назавжди |

## 8. Небезпечні місця, які дизайн закриває (зведення)

- Токен у чаті: приймається лише в приваті + негайне видалення повідомлення; у групі — відмова й порада відкликати.
- Токени в дампах: Fernet; ключ окремо від бази.
- Підроблений callback: перевірка власника/ролі в кожному хендлері.
- Випадкове знищення історії: purge лише CLI, лише `removed`, глобальне не чіпається; документи `main`/`light` — ніколи не видаляти фізично (ключ інакше не відновити).
- Відкликаний токен: `auth_error` зупиняє пол, одне повідомлення власнику — без спаму в `system` кожні 30 хв.
- Чужі люди на сервері: `approve`.
- Bot заблокований користувачем: маршрути вимикаються, акаунт на паузу.
- Бот без акаунтів: стартує (зараз — `SystemExit`).
- Той самий WK-акаунт від двох людей: відмова + сигнал адмінам (шеринг — пізніше).
