# T24 · Варіанти рішень по чатах: дискавері, вибір чату, реєстр топіків, /setup, налаштування

`2026-09-12` · 🧠 brainstorm

Контекст:
- дизайн — [T22](T22-P--chats-delivery-model.md), UX — [T23](T23-P--bot-ux-chats.md); тут — точки, де були реальні альтернативи, і чому обрано так; питання до тебе — [T25](T25-Q--chats-questions.md).

## 1. Як бот дізнається про чат

| варіант | + | − |
|---|---|---|
| a) лише `/setup` у чаті (як зараз) | нуль магії | бот «не знає» чатів, куди його додали мовчки; людині треба йти в чат і писати команду |
| b) лише `my_chat_member` + повідомлення | автоматично, без дій | губить чати, куди додали, поки бот лежав понад 24 год; нема кроку «а тепер налаштуй» |
| c) **нативний picker `request_chat` + `my_chat_member` + `/setup`** (обрано) | зі свого приватного меню вибираєш чат зі списку Telegram, бот додається з правами сам; ручне додавання теж ловиться; командний шлях лишається | picker — reply-клавіатура (один екран іншого стилю); поведінку автододавання перевірити наживо |
| d) користувач надсилає id чату / пересилає повідомлення | без нових API | незручно, треба пояснювати, як дізнатись id; пересилання з груп часто без `forward_from_chat` |

## 2. Вибір цілі в приваті

| варіант | + | − |
|---|---|---|
| a) список лише відомих чатів | просто | коли чату нема — глухий кут «додай мене й напиши /setup» |
| b) **список відомих + `➕ Add a chat` через picker** (обрано) | глухого кута нема; список короткий, бо це лише «твої» чати | reply-клавіатура на один крок |
| c) лише picker щоразу | нуль списку в базі | зайвий крок Telegram-UI на кожну зміну; picker не показує, що вже налаштовано |

## 3. Реєстр гілок форуму

| варіант | + | − |
|---|---|---|
| a) нема (T19 §6: `thread_id` у маршруті) | мінімум | зі списку не вибереш гілку, зроблену людиною; перейменувати можна лише свою |
| b) окрема колекція `tg_topics` | «правильно» реляційно | ще одна колекція заради мапи на 3–10 записів на чат |
| c) **мапа `topics` в документі чату** (обрано) | один документ = чат зі всім, що про нього відомо; `$set: topics.<id>.name` атомарно | документ росте з кількістю гілок (сотні — не наш випадок) |

## 4. Політика гілки на маршруті

| варіант | + | − |
|---|---|---|
| a) лише авто (layout чату) | нуль вибору → нуль помилок | не можна направити у свою гілку «Vitalik & friends» |
| b) лише ручний вибір | повний контроль | новачок мусить створювати гілки сам; `/setup`-однією-кнопкою неможливий |
| c) **auto \| manual \| General з прапорцем `thread_auto`** (обрано) | дефолт працює без думання; хто хоче — вибирає; бот ніколи не чіпає чужі гілки | ще одне поле і дві гілки поведінки при «гілка зникла» |

## 5. Розкладки форуму

| варіант | + | − |
|---|---|---|
| a) `topics` (акаунт × категорія) + `single` (є) | є | у форумі на одну людину 2 гілки на акаунт — багатьом забагато |
| b) **+ `account_topics` (один топік на акаунт)** (обрано) | природний «мій топік» у спільному форумі; ціна — один рядок у `layout_title` | три варіанти замість двох у радіо-кнопках |
| c) довільна мапа категорія → гілка на рівні чату | максимум | це вже per-route вибір (§4), дублює його |

## 6. Доля `/setup` у чаті

| варіант | + | − |
|---|---|---|
| a) повний редактор з галочками (як зараз) | усе в чаті | дві UI на одне (чат і приват) → підтримувати обидві; галочки в групі видно всім, тисне хто завгодно; «страшнувато» |
| b) **легкий: реєстрація + права + `Deliver my digests here` + `Configure in private`** (обрано) | 2 кнопки, командний шлях лишається; тонке — в одному місці (приват) | тонке налаштування з чату неможливе (і не треба) |
| c) прибрати | менше коду | тим, кому зручно командами, — гірше; ручне додавання без picker-а потребує саме його |

## 7. Спільна категорія (`subjects`) у спільному чаті

| варіант | + | − |
|---|---|---|
| a) один маршрут на чат, `enabled` перемикає будь-хто (є) | просто | «я вимкнув — у сусіда зникло»; хто вирішує — невідомо |
| b) маршрут на кожного підписника | незалежність | дубль однакових повідомлень у чаті — те, чого ти просив уникати |
| c) **один маршрут + `subscribers`** (обрано) | нуль дублів; вимкнення = відписка; маршрут живий, поки хтось є; налаштування спільні з `set by` | налаштування спільні — той, хто останній, і вирішив (для `subjects` це майже нічого не важить) |

## 8. Налаштування доставки

| варіант | + | − |
|---|---|---|
| a) окремі поля й окремі кнопки на кожне | пряме | кожна настройка = поле + кнопка + текст + хендлер |
| b) **реєстр `Setting(...)` + генерована UI + `effective()` з шарами** (обрано) | нова настройка = рядок у реєстрі; шар акаунта — той самий механізм пізніше | абстракція на два налаштування виглядає завеликою, але T07 §4 обіцяє десятки |
| c) `/settings` з текстовим синтаксисом (`silent on`) | нуль кнопок | треба памʼятати синтаксис; проти принципу «усе кнопками» |

Перші дві: `silent` (усюди корисне, нуль логіки) і `items` для reviews (найчастіший запит «не пиши мені кожне слово»). Не зараз: `subjects.scope` (потрібна логіка «мої предмети»), режими session/daily (крок 2 T07), quiet hours (ввід часу).

## 9. Хто може направляти доставку в чат

| варіант | + | − |
|---|---|---|
| a) **будь-який відомий учасник; чат не в `members` → живий `get_chat_member`** (обрано) | людина і так може там писати; нуль зайвих відмов | учасник великого форуму може налити туди свої дайджести — але адміни чату дали боту права і можуть його викинути |
| b) лише адмін чату | безпечніше для комʼюніті-форумів | другий учасник родинного чату не зможе нічого без адмінки; ще один API-виклик на кожну дію |
| c) той, хто додав бота | просто | «додав один, користуються двоє» — не працює |

Компроміс усередині (a): створювати гілки може будь-хто, перейменовувати чужі — лише адмін чату.

## 10. Небезпечні місця, які дизайн закриває

- Підроблений callback з чужим `chat_id` → перевірка видимості (members / live-перевірка / адмін бота).
- Бот перейменовує чужі гілки → лише свої або адмін чату.
- «Увімкни Topics» → міграція id → маршрути переїжджають автоматично.
- Гілку видалили / закрили → маршрут `error` + fallback General (manual) або перестворення (auto); одне DM власнику, не спам.
- Бота викинули → маршрути off з памʼяттю, власникам одне повідомлення.
- Спільний `subjects` → підписники, не дубль.
- Reply-клавіатура picker-а «зависла» → знімається на будь-який наступний апдейт у приваті, не лише на Cancel.
- Чат, невідомий після простою > 24 год → UI завжди пропонує `➕` / `/setup`.
